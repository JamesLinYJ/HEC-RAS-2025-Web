# 洪水推演

前端入口 `/flood.html` 独立加载，不创建工程会话；`/#/dam-break` 直接加载同一组件。后端仍为同一个 ASP.NET Core 服务、操作队列、取消协议和 C# 求解器。

## 计算模型

`FloodSimulationService` 将页面参数转换为内存网格、地形水力特性表、降雨边界和渐进溃口，调用 `Ras.Engine.ComputeDriver` 的二维隐式 SWE 求解器。没有前端替代求解器。

- 内置河谷为 840 × 1200 m，Manning n = 0.035。当前模型使用解析河谷地形，不读取用户的实测 DEM。
- 网格基础间距 20 m，在坝线插入精确的左右溃口边缘，避免把输入宽度舍入到网格间距。
- 坝线 y = −140 m；初始库水深以坝线中点地面为基准，坝顶高程为 34 m，并取不低于当地地面的值。下游初始干燥。
- 矩形溃口按开始时间和形成历时线性下切到河床，最终宽度为输入值。堰流及浅水动力学由原求解器处理。
- 降雨均匀施加于整个域，前峰、中峰和后峰的峰值位置分别为历时的 25%、50%、75%。过程线为分段正弦，逐分钟积分得到时段平均强度，以 m/s 提交。当前不设入渗和蒸发。
- 下游采用正常水深边界，摩阻坡度 0.035/6；其余外边界封闭。
- 计算至降雨结束与“溃口形成完毕后 60 分钟”两者中的较晚时间。最多返回 121 个输出时刻，内部使用自动步长。

地形重采样范围包含网格外缘的缓冲带，覆盖半开区间的边界取样。闭合堰面在隐式连续性矩阵中同样被隔断，避免出现“报告流量为零但矩阵仍转移水量”的情况。

## 共用服务接口

通过既有 `POST /api/operations` 提交：

- `flood.scene`：校验参数，返回地形网格和初始库水位。
- `flood.compute`：返回进度、可取消的运行状态，以及成功后的完整结果。排队取消和运行中取消都使用原操作协议。

输入：`name`、`rainfall`（mm/h）、`stormDuration`、`breachStart`、`breachDuration`（min）、`breachWidth`、`reservoirLevel`（m）、`rainPattern`（front/middle/back）。

结果含运行 ID、模型版本、完整输入快照、网格、时刻、雨强、累计雨量、流量、蓄水量、淹水面积、最大水深/速度、溃口高程、累计出流水量和水量平衡误差。

每帧 `fields` 为 Base64 编码的小端 Float32，依次存放四组完整单元数组：水面高程、水深（相对单元最低地面）、x 速度、y 速度。几何和全部结果可从页面导出 JSON。

## 显示和状态

Three.js 读取服务返回的网格和结果。时间轴在记录时刻间线性插值，水面从相邻湿单元水位重构；坝线两侧保持独立水头。流向标记使用计算速度，降雨粒子使用返回雨强。材质法线不改变求解地形。横向显示缩放为 1:6，竖向保留高程，便于观察浅水变化。

参数修改不会覆盖旧结果，页面标记待重算；计算和取消期间锁定输入。失败或取消保留上次结果，状态未知时只恢复原操作，不自动重复提交。

## 验证

- `npm run test:flood-scenario`：雨型积分、单位、阶段边界及草稿输入校验。
- Release 构建 Host 后，运行 `npm run test:flood-compute`。可用 `HECRAS_FLOOD_WORKER` 指定 Host 可执行文件，并按工具链设置 `DOTNET_ROOT`。此检查执行真实求解，覆盖闭坝静水、无雨下游保持干燥、降雨水量、溃口宽度、开始时间、默认输入、长历时强降雨及输出有限性。水量平衡误差阈值为初始库容的 0.25%，包含现有迭代和干湿处理容差。
- 浏览器实际计算、回放读数、取消终态、旧结果保留、导出和材质加载需另行检查。组件或数值回归不能替代真实地形模型的校准。
